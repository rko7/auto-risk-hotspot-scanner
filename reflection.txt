For this assignment, the part that took me the most time was debugging the backend query filters, especially the where clause for the date range and the division filter. 
I initially thought my app was failing to return data because the API was not accepting my date values, and I also got confused when I saw cases where DIVISION and DISTRICT did not match what I expected, so I spent about a week investigating whether the problem was my code or the source dataset structure before I confirmed it was mostly a data interpretation issue rather than a broken filter. 
A key step in resolving this was my commit c0dc65f ("Refactor ArcGIS date filtering and division SQL logic"), where I reworked the date filtering and division query logic to better match the ArcGIS/TPS dataset behavior. 
Another important step was commit 19a0b2a ("improve responsive form layout and add latest first sorting"), where I improved the responsive form layout after multiple attempts and made the results more practical to read. 
I also added an optional severity filter and CSV export in commit 114f764 ("add severity filter and csv export with latest default date range"), which made the app more useful as a filterable search tool and reporting aid. 
The hardest implementation part for me was the frontend layout and responsive arrangement because I kept changing the form structure (especially the Severity field), and the layout would look fine at one width but break at another width, so I eventually grouped fields in a more stable way, even though I am still not fully satisfied with the Search button placement. 
I also added a dynamic “available dataset date range” note and defaulted the date inputs toward the latest available dataset range, which was inspired by a date-handling pattern I had used during a co-op data visualization/reporting task where the displayed dates had to update automatically to the most recent available data. 
I wanted to add more features such as a chart, but due to time limits and the delay caused by debugging the API query and data interpretation issues, I prioritized completing a stable end-to-end version with filtering, summaries, table output, sorting, and CSV export.
